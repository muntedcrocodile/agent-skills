# Frontend design

Ground the interface in its actual content and intended audience. When an
existing design system is present, inspect and extend its components and
tokens. For an open brief, choose a visual direction before implementation.

## Choose a direction

Decide which content should dominate the first screen and what action the
reader should understand. Choose typography, a small palette, spacing, and a
layout that express that hierarchy. A short sketch or token list is enough;
use a longer design plan only when the work needs it.

Use the subject's real terminology and material. Avoid giving every unrelated
project the same card grid, decorative gradient, oversized metric, or typography
pairing. Repetition is useful when it communicates a relationship; decoration
should earn its place. Prefer one memorable visual decision over many competing
effects.

## Build and inspect

Use the project's established framework and reusable components. Write concrete
copy that explains the action or state; do not leave invented product claims or
template content in a finished interface. Distinguish primary actions, secondary
actions, navigation, and status through consistent treatment.

Keep text and controls usable on narrow screens, at larger text sizes, and by
keyboard. Provide visible focus, meaningful labels, readable contrast, and a
reduced-motion alternative when animation is present. Let motion explain a
user-triggered change rather than continuously compete with the content.

Preview representative wide and narrow layouts when browser tools are available.
Exercise the main interaction and inspect errors. Critique the hierarchy and
spacing using the actual rendered result, then remove visual elements that do
not help the task. If a preview is unavailable, state that limitation rather
than claiming visual verification.
